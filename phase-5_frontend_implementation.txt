1. OVERVIEW
================================================================================

The frontend is a React 18 Single Page Application built with:
- React Router 6 for navigation
- Material UI 5 for component library and styling
- Axios for REST API communication
- STOMP.js + SockJS for WebSocket real-time collaboration
- Context API for global state management

Build output: 192 KB gzipped (production optimized)

5. STATE MANAGEMENT
================================================================================

5.1 AuthContext (Global)
--------------------------------------------------------------------------------
Provides:
  - user: { id, name, email } or null
  - login(email, password): authenticates, stores token + user
  - register(name, email, password): creates account, auto-login
  - logout(): clears token + user, redirects
  - loading: boolean while checking stored session

Storage:
  - localStorage.token: JWT access token
  - localStorage.user: JSON serialized user object

On mount: reads from localStorage to restore session.

5.2 Component-Level State
--------------------------------------------------------------------------------
Each page manages its own state via useState/useEffect:
  - Loading states for async operations
  - Error handling with user-facing messages
  - Form values
  - Dialog open/close states

6. API LAYER
================================================================================

6.1 Axios Instance (api.js)
--------------------------------------------------------------------------------
  Base URL: http://localhost:8080/api
  Content-Type: application/json

  Request Interceptor:
    - Reads token from localStorage
    - Attaches Authorization: Bearer {token} header

  Response Interceptor:
    - On 401: clears localStorage, redirects to /login
    - All other errors: rejected promise (handled by caller)

6.2 Service Modules
--------------------------------------------------------------------------------

authService.js:
  - login(email, password) -> POST /auth/login
  - register(name, email, password) -> POST /auth/register
  - getMe() -> GET /auth/me

documentService.js:
  - getAll() -> GET /documents
  - getById(id) -> GET /documents/{id}
  - create(title, content) -> POST /documents
  - update(id, {title, content}) -> PUT /documents/{id}
  - delete(id) -> DELETE /documents/{id}
  - share(docId, email, role) -> POST /documents/{id}/share
  - getPermissions(docId) -> GET /documents/{id}/share
  - removePermission(docId, userId) -> DELETE /documents/{id}/share/{userId}

editingKeyService.js:
  - requestKey(docId) -> POST /documents/{id}/key/request
  - releaseKey(docId) -> POST /documents/{id}/key/release
  - getStatus(docId) -> GET /documents/{id}/key/status

versionService.js:
  - getHistory(docId) -> GET /documents/{id}/versions
  - getVersion(docId, v) -> GET /documents/{id}/versions/{v}
  - restore(docId, v) -> POST /documents/{id}/versions/{v}/restore
  - compare(docId, vA, vB) -> GET /documents/{id}/versions/compare

aiService.js:
  - askQuestion(docId, question) -> POST /documents/{id}/ask
  - summarize(docId) -> POST /documents/{id}/summary
  - search(query) -> POST /search

================================================================================
7. WEBSOCKET SERVICE
================================================================================

7.1 websocketService.js (Singleton)
--------------------------------------------------------------------------------
  Transport: STOMP over SockJS
  Endpoint: http://localhost:8080/ws
  Auth: JWT token in CONNECT frame Authorization header
  Reconnect: 5-second delay, automatic
  Heartbeat: 10s incoming, 10s outgoing

7.2 Methods
--------------------------------------------------------------------------------

Connection:
  - connect(token): activates STOMP client
  - disconnect(): deactivates, unsubscribes all
  - onConnect(callback): fires when connected (or immediately if already)

Subscriptions:
  - subscribeToEdits(docId, callback)      /topic/document/{id}/edits
  - subscribeToCursors(docId, callback)    /topic/document/{id}/cursors
  - subscribeToPresence(docId, callback)   /topic/document/{id}/presence
  - subscribeToKeyChanges(docId, callback) /topic/document/{id}/key
  - subscribeToEvents(docId, callback)     /topic/document/{id}/events

Publishing:
  - sendEdit(docId, content, title)        /app/document/{id}/edit
  - sendCursor(docId, pos, selStart, selEnd) /app/document/{id}/cursor
  - sendPresence(docId, action)            /app/document/{id}/presence

Cleanup:
  - unsubscribeFromDocument(docId): removes all subscriptions for a doc

7.3 Usage in Editor
--------------------------------------------------------------------------------
On mount:
  1. Connect WebSocket with token
  2. Subscribe to edits, key changes, presence
  3. Send JOINED presence message

On remote edit received:
  - Update content/title in state (if from different user)

On save:
  - Call documentService.update()
  - Send edit via WebSocket to broadcast

On unmount:
  - Send LEFT presence message
  - Unsubscribe from document topics

8. PAGE DETAILS
================================================================================

8.1 Login (/login)
--------------------------------------------------------------------------------
- Centered card layout
- Email + password fields
- Error alert on failure
- Loading state on submit button
- Link to /register
- On success: stores token, navigates to /dashboard

8.2 Register (/register)
--------------------------------------------------------------------------------
- Name + email + password + confirm password
- Client-side validation:
  - Password match check
  - Minimum 6 characters
- Server-side error display
- Link to /login
- On success: auto-login, navigates to /dashboard

8.3 Dashboard (/dashboard)
--------------------------------------------------------------------------------
Layout:
  - Navbar at top
  - "My Documents" heading + "New Document" button
  - Responsive grid (1/2/3 columns)

Document Cards:
  - Title (truncated)
  - Owner name
  - Updated date (formatted)
  - Role chip (color-coded: blue=OWNER, green=EDITOR, grey=VIEWER)
  - Edit/View icon button
  - Delete button (OWNER only, with confirmation)
  - Click navigates to Editor

Create Dialog:
  - Title text field
  - Cancel/Create buttons
  - On create: navigates to new document editor

Empty State:
  - "No documents yet" message
  - Create Document call-to-action button

8.4 Editor (/documents/:id)
--------------------------------------------------------------------------------
Toolbar:
  - Back button (to dashboard)
  - Inline title field (editable when has key)
  - Role chip
  - Key status chip:
    - Green "Editing" with release action (when holding key)
    - Orange "Locked by X" (when someone else has key)
    - Grey "Available" (when key is free)
  - "Unsaved" chip (when changes exist)
  - Active users avatar group
  - "Request Key" button (when not holding)
  - Version History icon button
  - AI Assistant icon button (sparkle)
  - Share icon button (OWNER only)
  - Save button (disabled when no changes or no key)

Content Area:
  - Full-page multiline TextField
  - Paper wrapper (max-width 900px, centered)
  - Disabled when user doesn't hold key or is VIEWER
  - Placeholder text based on state

Share Dialog:
  - Email input + Role dropdown (Editor/Viewer) + Share button
  - Permission list with names, emails, role chips
  - Remove button for non-OWNER permissions

Keyboard Shortcuts:
  - Cmd/Ctrl+S: save document

Snackbar Notifications:
  - Save success/failure
  - Key acquired/released
  - Share success/failure

8.5 Version History (/documents/:id/history)
--------------------------------------------------------------------------------
- Back button to editor
- List of versions (newest first)
- Each version shows: version chip, title, modified by, timestamp
- Actions per version:
  - View: dialog with full content (monospace, pre-wrap)
  - Compare: select two versions for side-by-side view
  - Restore: confirmation prompt, creates new version
- Compare mode: chip shows selected version, can reset
- Compare dialog: two-column layout with content panels

8.6 AI Assistant (/documents/:id/ai)
--------------------------------------------------------------------------------
- Back button to editor
- "Summarize Document" quick action button
- Chat-style conversation area:
  - Empty state with instructions
  - Question bubbles (right-aligned, blue "You" chip)
  - Answer bubbles (left-aligned, grey "AI" chip)
  - Sources listed below answers
  - Loading indicator ("Thinking...")
- Input area: multiline TextField + Send button
- Enter key submits (shift+Enter for newline)

8.7 Semantic Search (/search)
--------------------------------------------------------------------------------
- Search input with SearchIcon adornment
- Search button + Enter key triggers
- Loading progress bar
- Results list:
  - Document icon
  - Title + relevance score chip (color: green >80%, blue >60%, orange >40%)

11. ERROR HANDLING PATTERNS
================================================================================

API Errors:
  - Axios response interceptor catches 401 -> auto logout
  - Component-level try/catch shows error in Alert or Snackbar
  - err.response?.data?.message used for server error messages
  - Fallback generic messages when no server response

Loading States:
  - Buttons show "Loading..." or spinner when processing
  - Full-page CircularProgress for initial data fetches
  - Buttons disabled during async operations

Validation:
  - Client-side: password match, min length
  - Server-side: displayed via Alert component
  - Form inputs use HTML5 required attribute

12. BUILD & DEPLOYMENT
================================================================================

Development:
  npm start           -> http://localhost:3000 (hot reload, proxy capable)

Production Build:
  npm run build       -> /build directory (192 KB gzipped)

Docker:
  Stage 1: node:18-alpine
    - npm install
    - npm run build (REACT_APP_API_URL=__REACT_APP_API_URL__)

  Stage 2: nginx:1.25-alpine
    - Copy build output
    - Custom nginx.conf (SPA routing, gzip, caching)
    - docker-entrypoint.sh replaces __REACT_APP_API_URL__ at runtime

Runtime Config:
  - REACT_APP_API_URL environment variable
  - Injected via sed in entrypoint script
  - Allows same Docker image for different environments

14. PERFORMANCE CONSIDERATIONS
================================================================================

  - Code splitting: lazy-loaded modules (account, users) in routing
  - Production build: minified, tree-shaken, gzipped
  - Static assets: 1-year cache headers via Nginx
  - index.html: no-cache (always fresh deployments)
  - WebSocket: single connection per session (not per page)
  - Axios interceptor: token attached once (not per-call lookup)
  - Conditional rendering: loading skeletons prevent layout shift
