1. OVERVIEW
================================================================================

Phase 1 delivers the foundational layer of the CollabEditor platform:
- User authentication with JWT
- Document CRUD operations
- Role-based document sharing (Owner, Editor, Viewer)
- React frontend with Material UI
- MySQL database via Docker Compose

================================================================================
2. ARCHITECTURE
================================================================================

    React (port 3000)  --->  Spring Boot API (port 8080)  --->  MySQL (port 3306)
         |                          |
         |--- Axios + JWT -------->|
         |<-- JSON responses ------|

Frontend and backend are completely decoupled.
Communication happens via REST API with Bearer token authentication.

3.3 Database Schema
--------------------------------------------------------------------------------

TABLE: users
- id (BIGINT, PK, AUTO_INCREMENT)
- name (VARCHAR, NOT NULL)
- email (VARCHAR, NOT NULL, UNIQUE)
- password (VARCHAR, NOT NULL) -- BCrypt hashed
- created_at (DATETIME)

TABLE: documents
- id (BIGINT, PK, AUTO_INCREMENT)
- title (VARCHAR, NOT NULL)
- content (LONGTEXT)
- owner_id (BIGINT, FK -> users.id)
- created_at (DATETIME)
- updated_at (DATETIME)

TABLE: document_permissions
- id (BIGINT, PK, AUTO_INCREMENT)
- document_id (BIGINT, FK -> documents.id)
- user_id (BIGINT, FK -> users.id)
- role (ENUM: OWNER, EDITOR, VIEWER)
- created_at (DATETIME)
- UNIQUE CONSTRAINT on (document_id, user_id)

Schema is auto-generated by Hibernate (ddl-auto: update).

3.4 Authentication Flow
--------------------------------------------------------------------------------

Registration:
1. User sends POST /api/auth/register with {name, email, password}
2. Validate input (email format, password min 6 chars)
3. Check email uniqueness
4. Hash password with BCrypt
5. Save user to database
6. Generate JWT access token (24h) and refresh token (7d)
7. Return tokens + user info

Login:
1. User sends POST /api/auth/login with {email, password}
2. Spring Security AuthenticationManager authenticates
3. If valid, generate JWT tokens
4. Return tokens + user info

Protected Requests:
1. Client sends Authorization: Bearer <token>
2. JwtAuthenticationFilter extracts token
3. Validates signature and expiry
4. Loads user by ID from token subject
5. Sets SecurityContext authentication
6. Request proceeds to controller

3.5 API Endpoints
--------------------------------------------------------------------------------

AUTH:
  POST /api/auth/register      Public   Register new user
  POST /api/auth/login         Public   Login
  GET  /api/auth/me            Auth     Get current user profile

DOCUMENTS:
  POST   /api/documents        Auth     Create document
  GET    /api/documents        Auth     List accessible documents
  GET    /api/documents/{id}   Auth     Get single document
  PUT    /api/documents/{id}   Auth     Update document (OWNER/EDITOR only)
  DELETE /api/documents/{id}   Auth     Delete document (OWNER only)

SHARING:
  POST   /api/documents/{id}/share          Auth/Owner   Share with user
  GET    /api/documents/{id}/share          Auth/Owner   List permissions
  DELETE /api/documents/{id}/share/{userId} Auth/Owner   Remove permission

3.6 Security Configuration
--------------------------------------------------------------------------------
- Stateless sessions (no server-side session)
- CORS enabled for http://localhost:3000
- /api/auth/** endpoints are public
- All other endpoints require authentication
- BCrypt password encoding
- JWT signed with HMAC-SHA256 (Base64 encoded secret)

3.7 Permission Logic
--------------------------------------------------------------------------------

Document Access:
- User can see documents they own OR have a permission entry for
- DocumentRepository.findAccessibleByUserId() handles this query

Document Edit:
- OWNER and EDITOR can update title/content
- VIEWER gets 403 (permission denied)

Document Delete:
- Only OWNER can delete
- Deleting removes all associated permissions first

Document Share:
- Only OWNER can share
- Cannot share with yourself
- Cannot assign OWNER role (only EDITOR/VIEWER)
- If permission exists, role is updated (upsert behavior)

4.4 Authentication State
--------------------------------------------------------------------------------
- AuthContext provides: user, login(), register(), logout(), loading
- Token stored in localStorage under key "token"
- User info stored in localStorage under key "user"
- On app load, checks localStorage for existing session
- Axios request interceptor attaches Bearer token to all requests
- Axios response interceptor catches 401 -> clears storage, redirects to login

4.5 Pages Detail
--------------------------------------------------------------------------------

Login:
- Email + password form
- Error display via MUI Alert
- Loading state on submit button
- Link to register page
- On success: stores token, navigates to /dashboard

Register:
- Name + email + password + confirm password
- Client-side validation (password match, min length)
- Server-side validation errors displayed
- Link to login page
- On success: auto-login, navigates to /dashboard

Dashboard:
- Fetches all accessible documents on mount
- Displays as card grid (responsive: 1/2/3 columns)
- Each card shows: title, owner name, updated date, role chip
- Color-coded role chips (primary=OWNER, green=EDITOR, grey=VIEWER)
- "New Document" button opens create dialog
- Delete button on OWNER cards (with confirmation)
- Click card navigates to editor
- Empty state with call-to-action
- Loading spinner and error handling

Editor:
- Fetches document by ID on mount
- Inline title editing (standard variant, no underline)
- Full-page multiline textarea for content
- Save button + Cmd/Ctrl+S keyboard shortcut
- "Unsaved" chip indicator when changes exist
- Read-only mode for VIEWERs (disabled fields, no save)
- Role chip display in toolbar
- Back button to dashboard
- Share button (OWNER only) opens share dialog:
  - Email input + role dropdown (Editor/Viewer)
  - Submit shares document
  - Lists current permissions with role chips
  - Remove button for non-owner permissions
- Snackbar notifications for save/share/error feedback

6. HOW TO RUN
================================================================================

Prerequisites:
- Docker Desktop running
- Java 21 installed
- Node.js 18+ installed
- Maven 3.8+ installed

Steps:

1. Start database:
   docker-compose up -d

2. Start backend:
   cd backend
   mvn spring-boot:run

3. Start frontend:
   cd frontend
   npm install
   npm start

4. Open browser at http://localhost:3000
